# LABO EXP-019: 1000 кастодианов, 1–90% нарушителей

Связано с WOW-CUSTODIAN-05: https://app.notion.com/p/40232a84beec81ddbc82c9748d7c704a. Только синтетический LABO, не WOW/Akula.

## Матрица
Точные доли 1, 5, 10, 20, 40, 70, 90% из 1000 узлов, соответственно 10, 50, 100, 200, 400, 700, 900. Виды нарушений: mixed, refusal, bad-bytes, audit-evasion, unstable, collusion, late-compromise. Mixed смешивает проблемы; другие варианты выделяют один тип.
Для каждого seed состав заражённых вложен по порогам, а не переставляется произвольно.
На каждую ячейку 50000 условных писем, 160 тактов, 100 проверок за такт, seed 21/71/107. Итого 49 ячеек, 147 парных прогонов random/scored.

## Контроль
Одинаковые MessageId, время запроса, шесть разрешённых адресов и детерминированные исходы для пары письмо/peer в обеих политиках. Переход в новую ячейку меняет поведение кастодианов, но не входной поток писем.
У каждого письма не больше одного логического C-slot; таймаут/потерянный ACK не создаёт новую копию; реальной криптографической W4 нет. Отчётная доставка = только условно корректно прочитанные байты.
Показатели: доля условных доставок от всех созданных, парный выигрыш, количество списков без честного кастодиана, выявленные нарушения, ложные санкции честных, затраты на проверки.
При 90% заражения из шести приглашённых кандидатов могут быть все шестеро заражены. Рейтинг не может исправить такой изолированный выбор.

## Код и CI
Rust: src/bin/exp019_adversarial_custodians.rs. Агрегатор: scripts/exp019_grid_summary.py. Запуск через профильный .github/workflows/exp019-custodian-grid.yml. Rust unit-тесты проверяют точные пороги, вложенность долей, отказ в выдаче, скрытую цензуру аудита, задержанную порчу, воспроизводимость, K3-границу и ошибки ввода.

Это не реальные контакты, реальные физические серверы, W3/HPKE/Ed25519, QoS, независимость свидетелей или Sybil-устойчивость. Результаты чисел нельзя переносить в продукт без последующего стенда.
