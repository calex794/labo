# LABO EXP-018 — Rust-модель качества кастодианов

**Статус:** изолированный синтетический эксперимент. Не готовая реализация WOW/Akula, не реальная W4, не реальное хранение и не измерения физических устройств.

**Исходные требования:** [WOW-CUSTODIAN-05](https://app.notion.com/p/40232a84beec81ddbc82c9748d7c704a), [WOW-CUSTODIAN-04](https://app.notion.com/p/40232a84beec81ad966efbedef03cc45), [FAIR-SEC-02](https://app.notion.com/p/3fd32a84beec81ac9c48e5231bf13b03).

## Постановка

Сравниваем случайный выбор из разрешённых кастодианов и локальную политику репутации на тех же исходных сообщениях. Пять seeds: 21, 71, 107, 211, 20261023. На каждый запуск 100 кастодианов, 12 000 синтетических сообщений, 120 временных шагов, 16 проверок за шаг.

Узлы в контрольном сценарии: 55 обычных, 15 ленивых на выдачу, 10 возвращающих повреждённый конверт, 10 с заявленными периодами сна, 5 с нестабильным соединением и 5 сговорившихся.

Каждый MessageId имеет одинаковый для всех политик список шести ранее разрешённых получателем C, одно и то же время создания, вероятность запроса получателем и воспроизводимые исходы конкретного обращения (seed, MessageId, PeerId). Параллельных C для одного письма не создаём. Ни по timeout, ни по потерянному ACK старый C-slot не перевыдаётся.

## Где находится код

- [Быстрое вычислительное ядро на Rust](../src/bin/exp018_custodian_reputation.rs): временные шаги, 100 кастодианов, испытательные обращения, обработка писем, оценки, сравнение двух политик и 9 узких модульных тестов. Стандартная библиотека, детерминированный генератор, без внешних зависимостей.
- [Сбор отчёта на Python](../scripts/exp018_summary.py): чтение JSON, проверки ограничений и формирование парных итоговых таблиц. Python не участвует в расчёте горячего пути.
- [Профильный CI](../.github/workflows/exp018-custodian-reputation.yml): только одно задание для файлов этого эксперимента, Rust unit/Clippy, release build, пять парных seed, CPU/wall/RSS, сохранение JSON и Markdown.

## Правила оценки

1. Отсутствие запросов не является отказом: 100 принятых, но ещё никому не нужных писем не портят оценку.
2. Наблюдения делятся на exact, confirmed denial, bad bytes, unreachable и announced sleep. Отключение или потеря ACK не является доказательством злонамеренности.
3. Репутация строится только из собственных наблюдений/допущенных в модели проверок, с нейтральной стартовой оценкой. Чужие неподтверждённые голоса игнорируются.
4. При накопленных подтверждённых отказах — снижение приоритета новых задач. При модельном доказанном повреждённом W3 — приостановка новых STORE. Никаких глобальных банов и удаления старых писем.
5. Слишком малое число проверок означает недостаточность свидетельств, а не успех 100%.
6. Все пороги и частоты отказов — примеры для LABO. Они не утверждаются продуктовой политикой.

## Метрики

Основная метрика — условные доставленные письма на **все созданные**, а не только на удачно выбранные. Парная разница в процентных пунктах при одинаковых исходных намерениях, seed и доступных узлах. Отдельно: valid reads, отказы/битые ответы, выявленные узлы, ложные ограничения честных, объём контрольного трафика, CPU, RSS.

Поле delivered_synthetic_w4 обозначает **только симулированное успешное получение**. Подлинная подпись W4 не формируется. Счётчики исходят из предположения, что точный digest и авторство повреждённого ответа установлены — настоящую криптографическую верификацию код не делает.

## Запуск

1. Rust: cargo test --bin exp018_custodian_reputation
2. Rust: cargo run --release --bin exp018_custodian_reputation -- --custodians 100 --messages 12000 --ticks 120 --audits-per-tick 16 --seed 21
3. CI выполняет пять seeds, затем вызывает Python-агрегатор и создаёт JSON/MD-артефакт.

Ограничения входов: до 200 000 логических C, до 2 000 000 писем, до 10 000 тактов, максимум 2 000 000 проверок. Выбор из шести разрешённых кандидатов без перебора всех пар устройств.

## Rust против Python

Основная модель LABO уже на Rust. Старые Python scripts, включая EXP-004, обычно запускают Rust и обобщают результаты. Переписывание управления экспериментом не обещает большого ускорения. В EXP-018 Rust применяется к горячему циклу, Python — к отчёту. **Численного коэффициента ускорения Python -> Rust пока нет**: эквивалентного Python-ядра на тех же данных не построено, поэтому нельзя выдавать абсолютное время Rust за подтверждённую кратность ускорения. CI измеряет release wall/CPU/RSS именно симулятора.

## Проверки и незакрытая работа

- Один разрешённый C-slot на письмо; неподтверждённая квитанция хранения не превращается в конечную W4.
- Не наказывать за отсутствие запроса или объявленный сон.
- Битый ответ не компенсируется хорошим рейтингом.
- Сговорившиеся голоса не создают бан честного.
- Нет недопустимых входов, повтор с тем же seed воспроизводим.
- До любых санкций в продукте потребуются реальные подписанные evidence, защита приватности, независимые witnesses, настоящие двухсерверные испытания и безопасная W8-передача при ограничении C.
