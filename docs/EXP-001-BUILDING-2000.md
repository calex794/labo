**Статус:** выполненный *синтетический* вычислительный опыт на Rust, не измерение реальной Wi-Fi/BLE/сотовой сети.

- Исходники и исполняемая конфигурация: [commit ca4637e](https://github.com/calex794/labo/commit/ca4637ec551bcf2cd3a5d01891618d03b076f065).

## Параметры

```sh
cargo run --release -- --map building --devices 2000 --messages 3000 \
  --steps 120 --ttl 60 --seed 21021 \
  --mode ble --mobility quarter --outages periodic
```

По умолчанию `--contact-probes 8`, `--relay-percent 20`, без `--ip-interconnect`. Пять этажей, по 70 кабинетов, пять лестниц. 120 **виртуальных** шагов, TTL сообщения — 60 шагов. Отправители и адресаты выбираются псевдослучайно, сообщения создаются в первой половине горизонта. Радиомодель: гипотетическая BLE-близость; Wi-Fi — идеальная общая локальная IP-сеть. Сообщение может перемещаться с одним добровольным носителем, без размножения копий.

## Выводы и ограничения достоверности

1. В *этой конкретной модели* движение связано с увеличением доли достижимых адресатов по BLE (7→53→142) и смешанной Wi-Fi/BLE (1707→1840→2189). Это полезный сигнал для следующих опытов, **но ещё не доказательство причинного эффекта движения**.
2. Причина осторожности: текущая версия при переключении `static/quarter/all` меняет последовательность случайных вызовов во время генерации устройств; поэтому распределение добровольных посредников и список пар сообщений **не идентичны между тремя режимами** даже с тем же seed. Для причинного сравнения исправить модель на независимые подпотоки генератора для топологии, пар сообщений, радиомодулей и подвижности; затем повторить опыты и использовать несколько seed.
3. Идеализированный режим «общий Wi-Fi» даёт 100%, потому что сама модель считает всех подключённых к общей локальной сети доступными напрямую при отсутствии текущего обрыва. Это **не** эмпирический показатель настоящего Wi-Fi на 5 этажах.
4. «Доставлено» означает **логический контакт** с адресатом. Не моделируются криптографические квитанции WOW W4 после долговечной записи, фоновая работа Android/iOS, реальные радиопомехи, ограничение аккумуляторов и отдельные точки доступа.
5. В режиме строго одного интерфейса никакого автоматического BLE↔IP перехода нет, и полученные ~22% не означают возможность связи между несовместимыми радиосегментами.
6. Результат готов для дальнейшей постановки. Следующий обязательный эксперимент: *сопоставимые начальные устройства и сообщения*, 10–30 seed, распределения задержек с учётом недоставленных, замеры затрат памяти/ЦП, затем калибровка радиосреды и работа 20k/200k.
