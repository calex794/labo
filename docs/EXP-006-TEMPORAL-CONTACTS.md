# LABO EXP-006 — one-way time-respecting contacts across buildings

This is a **small, independently testable mathematical study** based on the requirements of [LABO-RF-001](https://app.notion.com/p/40032a84beec8134b41dcbafe984a67d). It is not yet a physical Bluetooth or Akula integration, and is deliberately separate from the real RSS calibration of EXP-005.

## Two different limits

**Encounter discoverability**: if the advertisement event schedule never overlaps a scanning window while people are near one another, the BLE encounter is missed even if RF signal would be strong enough. The current model generates deterministic phases for each device, advert bursts, scan interval and scan window, and accepts a contact if either radio direction overlaps. No packet collisions, coded PHY, platform-specific schedule, true controller timing or RSSI is modeled.

**Temporal route reachability**: a directed or undirected pair of radio contacts at `t1` and `t2` only forms a valid store-carry-forward route in *chronological order*. At most one hop is allowed within a synthetic tick. The upper-bound oracle can copy messages without cost or storage limits; if it cannot reach a destination by TTL, no real transport respecting these same contacts can do so. If it can, **real delivery is not proven**.

## Controlled campus assumptions

- `1 / 10 / 100` building wings, 2,000 logical devices each.
- Each wing has 1 stationary volunteer lobby hub and one designated courier.
- Local hub ↔ random resident encounters occur with 8 scheduled pairs per wing per tick.
- A courier from wing `b` walks to the **physically adjacent** wing `b+1` (a chain of buildings), takes 2 synthetic ticks to travel, contacts the destination hub, then returns home. Departures occur every 12 ticks. No instantaneous radio teleportation between buildings.
- Optional courier mode adds only these events and does not change random local contacts or message pairs for the same seed.
- Synthetic tick = 60,000 ms / one notional minute; 80 ticks total, TTL 40. This is not comparable as physical time to EXP-004 ticks.
- Two explicitly separate message categories: random resident/user pairs (representative only of that artificial sampling rule), plus **adjacent hub controls** that deliberately verify whether a walking courier can connect the two buildings. Do not blend these categories into a population-wide success rate.
- Discovery: nominal advertising every 400ms, scanning window 300ms every 2000ms, encounters 1500ms indoors and 3000ms at courier stops. These are arbitrary scenario parameters, NOT measured phone constants.
- Three deterministic seeds, no statistical confidence interval.

## Reproduce

```bash
python3 -m unittest discover -s scripts -p 'test_exp006_temporal_contacts.py' -v
python3 scripts/exp006_temporal_contacts.py --output results/exp006
```

Artifacts: `contact-matrix.csv`, `contact-matrix.json`, `report.md`. Measures physical encounters generated by *our hypothesis*, contacts passing scanning windows, temporal oracle reachable messages before TTL, and conditional delays among reachable. Checks: no path backward in time, no same-tick multi-hop, zero crossing without a courier, a positive courier route via departure/arrival, reproducibility, and discovery duration monotonicity.

## Limitations and next steps

1. Import actual anonymized timed encounters from [SocioPatterns](https://sociopatterns.org/datasets) / [Briar research](https://code.briarproject.org/briar/social-mesh-research/-/wikis/Analysis-of-Human-Mobility-Datasets), respecting licence and source time semantics.
2. Replace hypothetical advertiser/scanner schedules with measured traces from Android/iOS device experiments; model scanning pauses in background, link establishment and packet airtime.
3. Reconcile the event model with calibrated RSSI profiles from EXP-005; event contact must first pass the radio link and actual discoverability filter.
4. Compare courier strategies, bounded copies, real storage/energy and recipient-signed W4 acknowledgement.
5. Keep a small independent evidence corpus: synthetic non-measured outputs must never be labeled end-to-end actual device delivery.
